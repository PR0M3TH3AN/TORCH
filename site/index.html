The project decides the team.

TORCH does not install a catalog of generic agents. It reads the repository and the specifications you select, then produces a pending organization for you to split, merge, rename, or reject.

Input

Code and intent

Architecture, tests, operations, scarce resources, and external Markdown specifications become evidence—not instructions to execute.

Design

Explicit boundaries

Every domain receives scope, exclusions, owned paths, neighbors, checks, runtime policy, and collision rules.

Operate

Persistent specialists

Stable identities survive runtime sessions. When a durable new boundary emerges, the manager can propose another specialist—but only owner approval wires it into the Fleet.

Keep useful context hot.

A specialist can retain the working set for one coherent area instead of repeatedly loading unrelated project history. TORCH measures cache reads, cache creation, compactions, resumed prompt size, cost, and verified outcomes before calling that an efficiency win.

Context savings are a measured hypothesis, not a marketing claim.

Proof has a commit.

TORCH distinguishes implementation from qualification. Green output without the right scenario, authority, and SHA is not proof.

Start with the work you actually have.

  --repo /path/to/project \
  --spec /path/to/product-spec.md \
  --output fleet-design-brief.json \
  --json
